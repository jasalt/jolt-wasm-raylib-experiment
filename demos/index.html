Live Jolt-driven Raylib

A functioning EXP-015 build: Jolt runs through threaded Chez portable bytecode in WebAssembly, calls a signed-scalar static C façade, and Raylib owns the browser frame loop.

Interactive input façade

Launch the 26 MB experimental runtime, then move the pointer over its canvas and press →. The green circle follows pointer position; holding ArrowRight visibly changes keyboard state and shifts the rectangle.

Not loaded. Explicit activation avoids starting a pthread worker during page navigation.

What this demonstrates

Observed

Chromium reported crossOriginIsolated and SharedArrayBuffer, canonical Jolt output, scene readiness, real mouse dispatch, and ArrowRight dispatch with no page errors.

Ownership boundary

Jolt selects scalar scene/input state through jolt.ffi. The C façade and Raylib own drawing, input polling, and browser frame scheduling.

Not claimed

This is not the desktop raylib-jlt binding running unchanged, nor per-frame Jolt execution. It is the narrow ABI-proven route documented by EXP-015.
